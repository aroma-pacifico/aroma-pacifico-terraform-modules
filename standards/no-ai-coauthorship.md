# Standard: Prohibition of AI Co-Authorship and Tool Attribution

This standard establishes the team-wide prohibition of artificial intelligence co-authorship trailers, tool attribution footers, and automated agent authorship identities across all commits and pull requests in the Aroma Pacífico organization (`Refs aroma-pacifico/aroma-pacifico-roadmap#40`).

---

## 1. Normative Rule

Every commit and every pull request in an Aroma Pacífico repository represents accountable engineering work owned by the human project roles (`SR1`, `SR2`, `JR1`, and `JR2`). Commits, commit messages, pull request titles, and pull request bodies must never carry AI co-author trailers, AI generation footers, session links, or AI tool author/committer identities.

Human `Co-authored-by:` trailers attributing collaboration between human engineers remain permitted and encouraged when two or more team members jointly author a change.

---

## 2. Prohibited Patterns and Surfaces

The prohibition applies case-insensitively across four surfaces: commit message subjects and bodies (`git log --format=%B`), commit author and committer metadata (`%an`, `%ae`, `%cn`, `%ce`), pull request titles, and pull request descriptions.

| Surface | Prohibited Pattern Class | Representative Examples | Allowed Counterpart |
|---|---|---|---|
| Commit message trailers and PR body | `Co-authored-by:` or `Assisted-by:` naming an AI assistant or vendor (`Claude`, `Anthropic`, `Codex`, `OpenAI`, `ChatGPT`, `GPT`, `Gemini`, `Google AI`, `Antigravity`, `Copilot`, `Cursor`, `Devin`) | `Co-authored-by: Claude <noreply[@]anthropic.com>`, `Co-Authored-By: Claude`, `Co-authored-by: OpenAI Codex <noreply[@]openai.com>`, `Co-authored-by: Gemini <noreply[@]google.com>`, `Co-authored-by: GitHub Copilot`, `Co-authored-by: Cursor`, `Co-authored-by: Devin` | Human `Co-authored-by:` trailer using a developer identity |
| Commit message trailers and PR body | `Co-authored-by:` or `Assisted-by:` using known AI `noreply` or vendor domains regardless of display name | Trailers referencing `noreply[@]anthropic.com`, `noreply[@]openai.com`, `noreply[@]google.com`, `noreply[@]cursor.sh`, `noreply[@]cognition.ai`, or `noreply[@]devin.ai` | Human GitHub `users.noreply.github.com` or institutional addresses |
| Commit message footers and PR body | Tool generation banners, attribution footers, or session URLs | `Generated with Claude Code`, emoji-prefixed `Generated with` lines (`\U0001f916 Generated with ...`), `Generated by Gemini`, `Generated with Cursor`, `Generated with Antigravity` | Clean `Refs aroma-pacifico/aroma-pacifico-roadmap#<n>` issue footer |
| Git author and committer fields | Commit `Author` or `Committer` name or email set to an AI tool or AI `noreply` address | Author name `Claude`, `Codex`, `Gemini`, `Antigravity`, `Copilot`, `Cursor`, or `Devin`; email under `anthropic.com`, `openai.com`, `cursor.sh`, `cognition.ai`, `devin.ai`, or AI `noreply` addresses | Human developer `user.name` and `user.email` |

Note: In documentation and regular expressions distributed to public repositories, `@` inside example addresses is written as `[@]` so that static public-tree email scanners never flag documentation literals while regular-expression engines match the literal `@` character.

---

## 3. Disabling Attribution in AI Coding Tools

Every engineer and agent runtime operating on Aroma Pacífico repositories must disable automatic commit and pull request attribution in their local and workspace tooling before creating commits.

| Tool | Configuration Mechanism | Required Setting |
|---|---|---|
| **Claude Code** | Repository `.claude/settings.json` (distributed by `scripts/sync-rules.sh`) and user `~/.claude/settings.json` | Set `"attribution": { "commit": "", "pr": "", "sessionUrl": false }` (and `"includeCoAuthoredBy": false` on legacy CLI versions). |
| **Gemini CLI** | Workspace `GEMINI.md` and `AGENTS.md` instructions plus `~/.gemini/settings.json` | Do not configure commit trailer templates in `~/.gemini/settings.json`. Follow `GEMINI.md` section 2.4, which forbids `Co-authored-by:` trailers and `Generated with` footers in all `git commit` and `gh pr create` calls. |
| **OpenAI Codex** | Repository `AGENTS.md` instructions and `~/.codex/config.toml` | Keep the worktree Git identity set to the human operator (`user.name` and `user.email`), disable commit trailer injection in Codex CLI settings, and pass only the Conventional Commit message and `Refs` footer to `git commit`. |
| **Google Antigravity** | Workspace `AGENTS.md` and `GEMINI.md` user rules | Preserve the human operator's Git identity (`git config --worktree` only when explicitly requested) and never append `Co-authored-by: Antigravity`, `Co-authored-by: Gemini`, or `Generated with` footers to commits or pull request bodies. |

### Claude Code `.claude/settings.json` Reference

Every repository carries the following `.claude/settings.json` file at its root:

```json
{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }
}
```

## 4. Three-Layer Enforcement Architecture

Compliance is enforced through three complementary layers across every repository:

1. **Tool Configuration and Normative Instructions**: `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.claude/settings.json`, and `.gitmessage` instruct humans and agents never to emit AI attribution trailers or footers.
2. **Local Commit-Message Guard (`.githooks/commit-msg`)**: A repository-tracked Git hook inspects every commit message (ignoring `#` comment lines) and the active Git author and committer identities before the commit is recorded. Developers enable the hook per clone with the one-line command documented in `CONTRIBUTING.md`:
   ```bash
   git config core.hooksPath .githooks
   ```
3. **Server-Side Pull Request Gate (`.github/workflows/pr-conventions.yml`)**: The `PR conventions` workflow inspects every commit in `origin/<base>..HEAD` (message body, author name/email, and committer name/email) as well as the pull request title and description. If any commit or the pull request body matches a prohibited pattern, the workflow logs the offending commit SHA, the offending line or identity, and the exact remediation commands, and fails the check.

---

## 5. Remediation Procedure

When `.githooks/commit-msg` or the `pr-conventions` CI workflow rejects a commit or pull request, apply the corresponding remediation before pushing:

1. **Fix the most recent local commit message**:
   ```bash
   git commit --amend
   ```
   Remove the offending `Co-authored-by:` or `Generated with` line while preserving the `Refs aroma-pacifico/aroma-pacifico-roadmap#<issue>` footer.
2. **Fix an AI author or committer identity on the most recent commit**:
   ```bash
   git config --worktree user.name "<Human Name>"
   git config --worktree user.email "<human-email>"
   git commit --amend --reset-author --no-edit
   ```
3. **Rewrite an earlier commit on a feature branch**:
   ```bash
   git rebase -i origin/main
   ```
   Mark the offending commit with `reword` (or `edit` if resetting author metadata) and remove the prohibited trailer or footer.
4. **Fix a pull request description**:
   ```bash
   gh pr edit <pr-number> --body-file <clean-body-file>
   ```
